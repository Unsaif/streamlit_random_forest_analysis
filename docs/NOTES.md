## Benchmark hardware (recommendation, adopted unless Tim objects)

Every number in the paper is regenerated by the Phase 3 benchmark, so the old laptop is
irrelevant: nothing from the manuscript is reused or compared against. The M1 Mac is the
reference machine. `results/env.json` records chip, core count, RAM, OS, Python and package
versions, the exact command and the config hash, and the paper's scalability table (T3) states
them. If a lab server becomes available, T3 gains a second column; the M1 run stays the baseline.
Peak memory is recorded with `psutil` and reported, because the 246k-row dataset is where an
M1 with 16 GB will be the constraint, and that is a legitimate finding for a scalability table.

## Interpretations made in Phase 1 (conservative choices; flag if wrong)

1. **Fallback when no quantile satisfies the bound.** The plan says keep all positive-importance
   features and set `bound_satisfied = False`. The implementation keeps all of them *and
   re-evaluates the bound on that model*, reporting the actual outcome in `bound_satisfied`
   (`q_final` is `None` in this case). A flag that is always False would hide the case where
   the all-positive model does satisfy the bound.
2. **`index` split.** The remaining rows are split 75/25 train/validation *stratified*,
   matching the default method; if stratification is impossible (a class with one row) it
   falls back to a random split and emits a warning.
3. **Dtypes.** The preprocessor does not up-cast numeric columns to float64 when nothing needs
   imputing, so integer presence tables stay integer. This changes no result (scikit-learn casts
   to float32 internally) and halves memory on the 246k-row dataset.
4. **Spearman matrix** is not rounded to four decimals before clustering (the old code did);
   §3 S5 specifies `d = 1 − ρ` without rounding. NaN correlations become distance 1.
5. **Per-class heatmaps** use Spearman correlation (§3 S7); the old app used Pearson.
6. **Visualisations use all rows** (train + validation + test) of the preprocessed final
   features, as the old app used train + validation. Test rows are used for figures only, never
   for any decision.
7. **Sample dataset** (D8): 1,000 stratified rows × 500 reactions (100 top-importance + 400
   random), 4 significant digits, gzip, ~1 MB. See `fastforest/data/README.md`.
8. **Boruta** is not yet in the `bench` extra; it is added in Phase 3 after checking that the
   PyPI release installs on current numpy (the plan anticipates it may not).
9. **Reported bound metrics.** The reference for the bound is the full model's *validation*
   metrics; the search never sees the test split. Test metrics for all three models are computed
   once, after every choice has been made.
10. **CLI `--split`** offers `stratified` and `random` only; `index` is available in the library
    and the app, where supplying the row list is practical.
